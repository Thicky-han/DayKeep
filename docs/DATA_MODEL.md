# L1 任务与存储契约

## 分层

DayKeep.Core 为 net10.0 库，包含不可变任务模型、输入验证、状态转移、TaskService 和 SQLite Repository；不依赖 WPF、窗口、系统托盘或定时器。DayKeep.Desktop 负责表单、卡片、筛选和可见错误。未来 L2 调度调用核心服务，不能从 UI 假定已保存。

## 任务

TaskKind：Todo（普通待办）、WaitingForCondition（等待条件）。TaskState：Waiting、Ready、Completed。暂停为独立 Paused；归档为独立 ArchivedAt，UI 显示“已归档”但保留原业务状态。任务具有 Guid、Revision、创建/更新时间、链接、备注、可未知截止日期及 ReminderRule。

完成时保存 BeforeCompletion 和 PausedBeforeCompletion，清除活动暂停标记；撤销完成恢复原值并清空 CompletedAt。归档/恢复不改变业务状态。完成或归档后禁止编辑/暂停，需先撤销或恢复。改任务类型时将未完成任务切到该类型的初始状态，同类型编辑不重置业务状态。

ReminderRule：规范化 HH:mm 字符串（最多八个不同时间）、星期位掩码、未来追加间隔 30 分钟与追加上限 3。位 0 为周一，位 6 为周日；127 每天，31 工作日。L1 保存这些值，不计算下一次提醒或产生定时事件。实际重复设置 UI 留到 L3。

## 数据库 schema 1

固定文件名 tasks.db；PRAGMA application_id=1145786417，user_version=1。没有 L0 任务库的用户从空库事务建表，已有外观文件独立保留。未知结构、非本应用数据库、更高 schema、损坏文件均不清空、不尝试破坏性重建。

- tasks：任务字段、修订号、完成撤销快照与归档时间；约束业务枚举、暂停、星期、次数、完成字段一致性。
- task_events：任务 ID、操作类型、UTC 时间；与任务写入同一事务。
- task_checks：独立检查 ID、任务 ID、本地日期、UTC 记录时间、备注。L1 的 RecordWaitingCheck 只作为后续每日检查的存储契约，没有用户入口。记录尚未开放不能完成任务，暂停/普通待办不能调用该路径。

不做永久删除，记录通过外键关联。使用参数化 SQL，连接关闭时不留全局连接池。每次写入按原 Revision 条件更新，旧表单冲突不覆盖；任务、事件和检查任何一项失败，整个事务回滚。锁定默认最多等待约 1 秒再报告，之后允许重试。

## 错误与验证

表单错误就地显示；保存失败保留表单。加载失败时显式提示并禁止写入，保留已展示数据但禁用操作，用户可重新读取。错误提示不直接暴露 SQL 或个人绝对路径。SQLite quick_check 在打开已识别库时执行；它不等同于完整备份恢复机制。

真实文件检查包含跨独立进程重启、事务故障注入、只读/占用、未来 schema、损坏和无关数据库；WPF 受控检查覆盖表单、状态按钮与失败显示。历史浏览、备份迁移 UI、下一提醒、去重与时钟变化均不属于 L1。
