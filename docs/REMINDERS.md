# L4 调度、操作与当前边界

## 固定时间

ReminderPlanner 是纯核心逻辑，接收 UTC 时刻、本地时区和事务快照。生产控制器启用 recoverMissed，查找任务修改后最近一个有效固定时刻；每周规则最多回看七天即可找到最近时刻，遗漏几十天也不逐日重放。默认关闭恢复的旧规划入口保留用于比较 L2 当前分钟契约，生产始终启用恢复。新建/编辑不回溯修改前的旧时刻。

固定 ReminderKey 使用任务、本地日期和固定时间，DST 重复小时仍是同一固定键。追加/延期另包含操作代数与 UTC 实例，避免夏令时回拨小时吞掉后续间隔，也允许用户在校正时间后重新明确延期。日期预算与已覆盖时刻单独持久保存，不能用一个未来日期的全局时间戳压住调回日期的新提醒。

控制器先在一个事务中排队投递、推进计划与次数，再显示。投递有 Pending/Shown/Dismissed/Canceled：显示前崩溃恢复 Pending，显示后未收起恢复 Shown，已收起不重弹。收起先保存 Dismissed，失败取消关闭并提示。每任务只保留最新活动投递，旧项取消，恢复始终每任务一张卡；这不等于证明用户看到了或阅读了屏幕。

桌面不可用或外部窗口覆盖整个显示器时，隐藏并保留已有提醒，恢复可用后汇总。使用 UOI_IO 查询桌面输入状态和前台矩形/类，不切换桌面或订阅键盘。订阅 SystemEvents 电源恢复、会话、时间和显示变化，经 Dispatcher 刷新；1 秒 timer 作为回退。刷新时重新取得系统本地时区。关闭主窗不停止；显式退出停止并释放订阅。

下次时间按星期查找未来七天；今天已检查的 Waiting 跳过今天，Ready 不受旧等待检查影响。DST 不存在的固定时间跳过，重复时间选较早实例；追加按实际 UTC 间隔继续。时钟快进汇总当前最近时刻；回拨按历史日期预算和覆盖进度继续，不清零、不重放该日期已覆盖固定时刻，也不会因另一天的未来时间戳长期停止。

## 追加与延期

- 默认 09:00 固定提醒后，09:30、10:00、10:30 追加。间隔可设 5—1440 分钟，每个任务每天上限 0—24 次；0 关闭追加。多个固定时间共用预算，固定时间不占追加次数。到达上限后，后续固定时间仍有效，但不会重新获得追加次数。
- 固定时间和追加撞点，只处理固定时间，重设追加锚点且不扣次数。定时器稍迟时只展示一次，下一追加沿原计划间隔推进到未来，跳过的间隔不补成一串弹窗、不按迟到的每秒 tick 漂移。
- 10/30/60 分钟延期覆盖期间的所有自动时刻，不扣追加次数。到期提示一次，再按剩余预算追加。显式延期可跨午夜、跨未选择的星期；自动追加仅限所选星期的本地当天，不把昨日追加拖到次日。
- 延期与下一追加写 reminder_progress；每天预算/覆盖时刻写 reminder_days；投递写 reminder_deliveries。到期显式延期汇总一项，同日追加汇总一项，昨日自动追加不逐次重放；另按最近固定时刻恢复当前任务。已经排队的追加占用预算，崩溃后恢复同一投递，不重复扣次。
- 关闭提醒、打开链接及无结果的 tick 不重设计划。今日检查取消当天剩余检查；确认开放从确认时间重算追加，保留当天已用预算。编辑、暂停、完成、归档、撤销和恢复会清除旧延期/追加，编辑/恢复等待未来固定时刻，不因反复编辑增加预算。状态、事件、检查及进度清理同一事务。

## 日期型截止

截止是本地 DateOnly，截止当天整日标记“今天截止”，下一本地日期标记“已逾期 N 天”。逾期、今天、未来日期、未知日期依次排序；不会自动确认开放、完成、隐藏或修改追加间隔。暂停/完成/归档保留日期但不显示活动催办优先级。

## 每天检查与办理

“尚未开放”与“已开放”使用不同结构化结果，和任务/操作事件同一事务保存。尚未开放保持 Waiting 并抑制本日检查；次日重算。确认开放转 Ready，不设置 CompletedAt。处于提醒窗口内的事项会原位换为待办理，直到明确完成或收起。主窗也能记录检查、确认开放。

打开链接只将重新校验过的 http/https URI 交给默认浏览器，拒绝本地文件、命令和 URL 内凭据；不运行脚本，不读取平台页面。浏览器启动失败显示具体错误，不写检查记录；调度错误不覆盖已有操作错误。关闭实际提醒不更新业务状态；同分钟不立即重弹，后续固定时间和剩余追加仍会提示。

## 窗口与失败

实际提醒独立于演示窗口和主窗口，置顶、ShowActivated=false、不自动消失，支持合并列表滚动。主窗隐藏不关闭实际提醒。事件处理使用显示时的任务修订号，旧内容不能覆盖新编辑；暂停/完成/归档会从可见提醒中移除，显示剩余事项。

只读、锁定、损坏、更高版本和缺失字段等异常必须可见，不得确认虚假成功。初始化未成功时禁止提醒快照和任务写入。任务/检查快照在一个读事务获取，检查与状态在写事务提交。

## 实测与复现

运行 scripts/test-core.ps1 验证本地日期、星期、DST、每日抑制、事务和升级；scripts/test-shell.ps1 通过可替换时钟验证真实窗口按钮。scripts/test-reminder-live.ps1 使用生产 1 秒计时器、隔离任务库和下一实际分钟，不改系统时间，也不访问私人任务。必须在本地可交互桌面运行，不能将模拟时钟当作实际按时投递。

L4 的 2026-10-22 21:26（Asia/Shanghai）实测在 21:26:00.464 展示，两项合并，前台句柄保持不变。这是一轮固定时间的本机观察；恢复、快进/回拨、时区和 DST 使用受控时钟及独立进程验证。没有强制让用户电脑睡眠、锁屏、改系统时间或注销，也不能当作物理多屏、独占全屏或 L5 连续试用通过。

最终代码的 21:40 再次观测因 desktopAvailable=false 未投递，未计为通过。保留该受限结果；正常桌面上的最终版本再次观测与真实退出全屏恢复仍需实机补验，详见 L4_REPORT.md。
