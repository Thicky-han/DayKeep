# 备份与恢复契约

L5 首次提供 `.daykeep.json`。根字段为 format=daykeep-backup、version=1、schemaVersion=5、exportedAt、data 和 sha256。版本不匹配、未知或重复 JSON 属性、缺少字段、截断、校验失败都拒绝导入。文件最多 64 MiB、事项最多 20,000 件，所有逻辑表合计最多 200,000 条；不自动截断备份。

data 包含完整 tasks、events、checks、progress、days、deliveries 和 revisionFloor。时间使用带偏移 ISO 8601，日期 yyyy-MM-dd，枚举为当前模型整数值。包括完成撤销快照、归档、每日本地预算、延期、下一追加、全部投递状态；不含外观、登录启动、程序、SQL、触发器或数据库物理页。

sha256 是将 data 用当前模型和固定 camelCase 序列化为紧凑 UTF-8 JSON 后的 SHA-256，不是整个文件字节的哈希。导出按主键排序。允许 JSON 空白变化，不要手改字段或数组顺序。哈希检测意外损坏，不是身份认证、签名或加密；只导入可信来源。

## 预览与确认

预览只读文件和当前库，在内存冻结已审阅内容，展示导出时间、任务/检查数、合并保留数和替换移除数。磁盘上的备份后来改变不会改变已冻结预览；要使用新内容需重新预览。切换模式重置确认。

- 合并：按事项 GUID 判断。同 ID 整组保留本机任务及全部记录，仅导入新 ID 的完整关联数据。不按标题去重、不按时间戳猜测覆盖。跨组事件/检查 ID 冲突拒绝合并，不静默丢记录。
- 替换：以备份完整数据为准，移除备份没有的本机事项，恢复历史状态、延期、预算与未收起投递。控制器按当前时间重算，可能立即汇总提醒。
- 必须勾选影响确认。任务表单打开时阻止导入并保留草稿；导出只含已经保存的数据。

执行时在写事务内比较当前库哈希。预览后任务、检查、提醒排队或收起变化都使预览失效，需重新预览。重复合并没有新 ID 时不改逻辑数据。

## 恢复与故障

在 SQL 删除/插入前，将事务内当前完整数据另存到任务库同目录 Recovery/DayKeep-before-import-时间-随机标识.daykeep.json。落盘成功才开始修改；恢复文件写入失败则不改库。SQL 或提交失败事务回滚，原数据保留，已生成的恢复备份也保留。

导出和自动恢复使用同目录临时文件、Flush(true) 和不覆盖的原子改名。已有文件一律拒绝覆盖，包含当前 tasks.db。掉电的最终持久性仍受文件系统和硬件影响，不承诺断电零损失。恢复文件由用户管理，不上传、不加密、不自动轮换清理。

导入提高被导入任务/进度的内部修订号，并记录 backup-imported 事件，拒绝旧表单覆盖恢复后的同一 GUID。稳定投递键与计划时间保留。schema 5 的 app_metadata.revision_floor 即使事项被替换移除仍保留水位，避免移除后重导使旧修订重新生效。

目标必须是本版本可读取的有效库；损坏、未知或更新库不会自动覆盖。用可靠备份恢复损坏库：从托盘退出，复制完整用户数据目录到安全位置，将原目录改名保留，重开生成空库，再选择备份预览并替换导入。可能存在的 db-wal/db-shm 附属文件要一起保留。不要在运行中只复制 tasks.db，也不要将新版本库交给旧版。

历史按事项、日期（包含起止）及名称/操作/检查备注筛选。检查保留记录时本地日期；普通操作按查询时区换算。名称为当前名称，没有历史名称快照。最新 200 条匹配记录可见，更多时缩小范围；原始记录仍完整导出。
